# TANGLAW roadmap

The following are **plans, not shipped features**.

## P0 — protect users
- Migrate off static front-end passcode and browser-stored admin state.
- Verify and deploy Firebase database/storage rules in test and production environments.
- Implement a trusted member receipt submission endpoint and anti-spam/abuse controls.
- Correct module loading and invoice ID collisions.
- Review personal-data handling, XSS, receipt URL access, and failure states.

## P1 — engineering quality
- Extract testable business logic; add unit tests and CI.
- Introduce Firebase Emulator integration tests for permissions and payment state transitions.
- Add accessible form feedback, responsive layouts and helpful error states.
- Document deployment, migration, rollback and backups.

## P2 — ecosystem value
- Provide an installable, configurable community payment tracking starter kit.
- Create sample synthetic fixtures, examples and maintainer documentation.
- Invite genuine outside feedback and contribution; measure adoption only from verifiable sources.

No release or adoption target is represented as already achieved.
